# NSM Test Suite

## e2e-production.sh — four-phase end-to-end verification (Wine rig)

This is the as-run script from the verification rig (paths refer to the rig
layout: `bin/` holds freshly compiled NSM.exe/connect.exe/discord_rpc.dll,
`testpacks/` is generated by the script itself and holds small DUMMY
encrypted packs — the production packs in `client-new/packs/` carry the real
alt:V client, which cannot run under Wine and would shadow the mock client —
and `mocks/` holds compiled mocks).

Build the binaries and mocks first (see docs/BUILDING.md and the mock list
below), then run `bash client-new/tests/e2e-production.sh` from the rig root.

### Phase A — PRODUCTION MODE (no services running)
Proves the launcher is a pure client:
- NSM.exe opens and serves the browser UI with nothing else running
- it spawns NO masterlist and NO gtamp-server process (count asserted = 0)
- no NSM window is visible while browsing (blank-window regression check)
- clicking Connect on an OFFLINE server logs a clear
  "Server X:port is unreachable - not launching the client." error,
  shows a Connection Error dialog, returns the browser to `idle`,
  starts nothing locally and launches no client

### Phase B — TEST MODE (mocks started BY THIS SCRIPT, never by NSM)
The script starts a mock masterlist and a mock gtamp-server as separate
processes (own Wine prefix), clearly labeled TEST MODE. Against them the
full player flow is asserted: connect -> encrypted pack extraction ->
runtime install -> launch -> single-window embed (SetParent + WS_CHILD
PARENT VERIFIED) -> host window shown ONLY AFTER the verified embed ->
in_game (with stage detail) -> game exit -> back to browser -> connect
again without restart. A duplicate Connect while in_game is refused
(`busy`). The mock service count must never increase (NSM spawns nothing)
and the launcher log must contain no auto-start attempts.

### Phase C — TEST MODE - client exits without starting GTA V
The rig client is swapped for a mock that exits instantly (code 42).
Asserts: the real exit code is logged and surfaced to the UI, no NSM
window appears, the error dialog is dismissible, the state returns to
`idle`, and a NORMAL connect in the SAME NSM process then succeeds
(failure recovery).

### Phase D — TEST MODE - client hangs, no GTA V (timeout)
The rig client is swapped for a mock that hangs; `game_start_timeout_sec`
is set to 6. Asserts: the timeout fires and is logged, the hung client is
terminated by the launcher, the timeout reason is surfaced to the UI, no
NSM window appears, and the state returns to `idle`.

### mocks/ (TEST ONLY)
- `mock_listener.c` — dual-mode TCP listener (built twice with
  `-DPORT=7788` / `-DPORT=8080` as mock gtamp-server / mock masterlist)
- `mock_altv.c` — mock altv.exe client stub
- `mock_gta5.c` — mock GTA5.exe with a real `grcWindow`-class window,
  PeekMessage loop, self-exits after ~22s (safe when embedded headless)
- `mock_altv_fail.c` — mock client that exits immediately with code 42
- `mock_altv_hang.c` — mock client that stays alive without starting GTA V
- `mock_discord_real.c` — mock Discord RPC forwarder (built `-shared` as
  discord_rpc_real.dll)

Build (mingw): `x86_64-w64-mingw32-gcc -O2 -mwindows -static -o <name>.exe <name>.c`
Mock GTA5/altv are placed into the test rig's `altv-runtime/<hash>/` dir.

**These mocks are test assets only. The production launcher never builds,
starts, or references them.**
